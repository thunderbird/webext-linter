More than one lock file error

sca-lock-file-multiple

What it detects

A source-code submission that commits more than one lock file at its root: any two of npm-shrinkwrap.json, package-lock.json and pnpm-lock.yaml.

Every check reads one lock file, the first of those three that is present. The build, though, picks its package manager by the lock file it finds: a pnpm-lock.yaml means pnpm install --frozen-lockfile. With two, the dependency tree the review audits need not be the tree the reviewer installs: a harmless npm lock beside a vulnerable pnpm one would pass the audit. So only one package manager’s lock file may be committed.

An npm-shrinkwrap.json beside a package-lock.json counts too, although npm itself reads that pair consistently: the rule is simply one lock file, and keeping one is all the developer is asked. A yarn.lock, or a lock file in a subfolder, is read by nothing and does not count.

The preparation of a source code review (--llm-sca-review) asks the same question before it audits the lock, and neither audits nor rescues such a source.

When it fires The add-on is told it commits more than one lock file, which lock file each package manager uses, and to remove the others. Each lock file is listed on its own location line.
It aborts the review This check settles the submission on its own (“Build process issues”), and runs right after the other lock file checks, before anything reads either lock. Nothing further is put to a reviewer, and no build step is handed out.
