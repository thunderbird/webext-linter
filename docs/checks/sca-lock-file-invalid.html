Invalid lock file error

sca-lock-file-invalid

What it detects

A committed lock file that cannot install what the package.json declares. Reviewers reproduce the build with the package manager's strict install, which compares the two files before installing anything and refuses outright when they disagree.

Four things make a lock file unusable, and all four are reported here: it cannot be read at all, it can be read but is not a lock file this comparison recognises, it resolves nothing for a package the package.json declares, or it records a different version range for one than the package.json asks for. The first two are worded apart because a developer would check which it is: one will not open, the other opens perfectly well and simply is not a lock. Production, build and optional dependencies are all checked, because the reviewer installs all of them. A dependency pointing at git, a URL, a file or a workspace is left alone: whether such a source is allowed is a separate question. The last case usually means the package.json was edited without running the install again, and it costs more than a failed build, because the vulnerability audit would otherwise clear the version the lock file names rather than the one the developer asked for. The oldest npm lock format restates no version ranges at all, so there only presence can be checked and no mismatch is ever claimed.

A submission built with a package manager this review does not support is left alone here. A disallowed tool and a missing or unusable lock are one fact, so it is reported once, by the check whose subject the tool is - and that check stops the review just as this one would.

When it fires The add-on is told its lock file fails to pin the version used for one or more declared packages, which of them is unresolved or recorded differently, and that it should run the install again and commit the regenerated lock file. The report then closes, saying it is incomplete because the build cannot be reproduced.
It stops the review This check is one of the few that settle the submission on their own. When it reports, nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections, and the developer’s text ends on the reason it is incomplete (“A build that cannot be reproduced”). Every question that remains would depend on installing and building the add-on, which cannot succeed, so the work it would otherwise put to a reviewer cannot change the outcome.
