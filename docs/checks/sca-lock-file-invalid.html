Invalid lock file error

sca-lock-file-invalid

What it detects

A committed lock file that cannot be read: it does not parse, or it parses but is not an npm or pnpm lock file while the package.json declares something to install from it.

The dependency audit reads the installed tree out of the lock file, so a lock it cannot read would leave that audit seeing nothing - and a review that sees nothing is not a review that found the tree clean. Whether a readable lock file matches the package.json is not decided here: that is the package manager’s own question, which npm ci and pnpm install --frozen-lockfile answer when the build installs.

When it fires The add-on is told its lock file cannot be read, so the dependencies it installs cannot be checked, and that it should run the install again and commit the lock file it writes. The report then closes, saying it is incomplete.
It stops the review This check is one of the few that settle the submission on their own. When it reports, nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections, and the developer’s text ends on the reason it is incomplete (“Build process issues”). Nothing in the dependency tree was checked, so building it would run code nobody vetted.

Source of truth: src/checks/rules/sca-lock-file-invalid.js and its entry in assets/registry.yaml.
