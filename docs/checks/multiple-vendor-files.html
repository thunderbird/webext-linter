More than one VENDOR file error

multiple-vendor-files

What it detects

The VENDOR manifest may be named VENDOR, VENDOR.md, VENDORS or VENDORS.md, matched without regard to case, and it lives in the package root. This check fires when more than one of them is present.

Which of them the review would read is otherwise decided by the order the archive lists its entries in — so the same submission could be checked against a different manifest after nothing more than a rebuild. Choosing between them is not the tool's to make: the developer says which file is the manifest by shipping one. While it is ambiguous, neither file is read, so no declaration from either is trusted and unparseable VENDOR file does not also fire.

When it fires The add-on is told which files collide and asked to keep the one that lists its bundled third-party libraries and remove the others. Every candidate is listed as a locus, so the reviewer sees the collision without opening the submission. The wording lives in assets/registry.yaml.

Source of truth: src/checks/rules/multiple-vendor-files.js (the accepted names live in src/normalize/vendor.js) and its entry in assets/registry.yaml.
