File could not be analysed error

unanalysable-file

What it detects

A JavaScript source the parser read but whose code could not be analysed. The parser recovers from some errors and still produces a syntax tree, but the analysis that walks that tree refuses it, so none of the file's code was checked.

The known case is a let, const or class declared twice in one scope. Every JavaScript engine and bundler rejects that before running anything, so the file can neither run in Thunderbird nor be built. The rest of the review goes on: the failure belongs to the one file.

It is asked of every artifact the review has, so in a source review a broken file is reported in the built XPI as well as in the source archive. A file the parser could not read at all is unparsable-file's instead.
