Async listener on a runtime message event warning

async-onmessage

What it detects

An async function passed straight to the addListener of a runtime message event — one that answers the sender with whatever its listener returns. An async listener always returns a Promise, which the messaging system reads as "I will respond" for every message it sees, including the ones the listener meant to decline — that claims the response channel, and the other listeners never get to answer.

The check looks only at the developer's own authored code; bundled, minified or otherwise non-authored files are skipped. It matches an addListener call on a recognised API root, then asks the schema whether that event answers with its listener's return value — it hands the listener a sendResponse and declares a return. That covers runtime.onMessage, onMessageExternal and onUserScriptMessage, and excludes onConnect and onConnectExternal, which hand over a port and read no return. A message event Thunderbird adds later is covered as it arrives. Only a first argument that is an async function or async arrow function is flagged; a plain listener is left alone.

When it fires The add-on is told an asynchronous listener is attached to the named event, what claiming the response costs the other listeners, and that this is error-prone and must be avoided, with a link to the runtime messaging guide.
