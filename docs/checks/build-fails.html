Source cannot be built error

build-fails

What it reports

A source-code submission that cannot be built by following its build instructions, including an install refused because package.json and the lock file disagree.

Nothing in the files decides it, so the check raises nothing itself. A plain review asks build-reproduces-xpi instead, whose one response covers every reason. Under --llm-review that question is put to the reviewer alone in the built phase, with four answers, and answering Does not build reports this check in its place. A source whose preparation gave its rescue up reports it without a question, since nothing clean can be built from it.

When it fires The add-on is told that the submitted source could not be built by following its build instructions, and that the instructions must be complete and the build must succeed from a clean copy of the archive, with the dependencies installed exactly as the lock file pins them.
It aborts the review It settles the submission on its own: nothing further is put to a reviewer, and the developer’s text ends on the reason it is incomplete (“Build process issues”). The build question is cleared, so this is the one build finding.

Source of truth: src/checks/rules/build-fails.js, the built phase and the entry in assets/registry.yaml, and src/pipeline.js for a rescue given up.
