Unused, hidden or duplicate files or folders warning

unused-files

What it detects

Files that should not ship in a published add-on: OS or editor junk and hidden dotfiles, and files that no part of the add-on ever loads. Such files complicate review, may leak information about the build system, and needlessly inflate the package.

A deterministic pre-flight follows every static load edge — imports, getURL, HTML and CSS references, and file-loading APIs — to decide what is reachable. Clear junk by name is reported first, so a leaked .git/ or .vscode/ is surfaced whatever it holds. Past that, dependency manifests, the manifest, locale catalogs and documentation are exempt — a documentation extension such as .md or .rst settles it on its own, while a .txt or an extensionless file must also be named like documentation, so LICENSE is exempt and a stray build log is still reported. A file named only by dead code with no dynamic loader is reported directly. When a file's name appears in live code, or the add-on builds load paths at runtime, the linter cannot tell statically whether any site really loads it, so each suspected loader site is named for the reviewer; the file is unused only if no site loads it.

When it fires The add-on is told the listed files or folders appear unused or hidden, that they complicate review and bloat the package, and is asked to fix its packaging so they are no longer included. Files the scan cannot resolve are escalated instead.
