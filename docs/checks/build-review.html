Build process review error

build-review

What it asks

In a source-code submission the reviewer builds the add-on from the readable source, but the dependency audit only reads the root package file and lock file. A build script or config could ignore the package file and pull code or resources from an undeclared source, leaving the declared dependencies a clean decoy. And the source has to build into exactly the shipped XPI, or the review read the wrong code.

Nothing in the files says for certain what a build does, so this check emits no finding of its own and escalates every source-code submission in which nobody decided about the build in a preparation (when: NOT build-judged): a plain report, and an agent review run with a check the build relies on switched off. It is the whole build question then, in the order a reviewer has to take it. First, does any step reach outside the declared dependencies? Then do not build it. Otherwise, does it build from a clean copy and reproduce the submitted XPI?

A plain report lists it under Extended Manual Review. An agent review puts it to the reviewer in ask, with its own answers: Builds fine and reproduces clears it, Build issues reports it, and the reviewer's own words report it with those words attached. Where the reviewer decided about the build in the preparation, Reproducing the XPI from the source or Unsafe build process asks in its place. The entry anchors at the submission's own package.json where there is one.

When it fires The add-on is told that every part of the build must come from the submitted source or the dependencies declared in the package file and lock file, and from nowhere else, and that the source must build into exactly the submitted XPI.
It aborts the review A build that is unsafe, fails or does not reproduce settles the submission on its own: the developer’s text ends on the reason it is incomplete (“Build process issues”).
