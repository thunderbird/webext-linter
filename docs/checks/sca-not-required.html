Source archive not required info

sca-not-required

What it detects

A source-code archive (--sca-root) that was not needed, because the shipped XPI is the submitted source. SCA exists to review the readable source of an add-on whose built XPI is not the code its developer wrote; when the XPI already is that code, the separate source submission bought the developer a slower review for nothing.

This is advice, not a routing decision. A source archive is always reviewed as one — the finding changes nothing about the review it appears in, and only tells the developer their next submission can be XPI-only. Routing on it is what the tool used to do, and it was a bypass: a committed, unminified dist/ inside --sca-source is its own twin under any content test, so a build could always be dressed up as source and shrink its own review.

Three questions, all of which must say yes. Is the shipped code readable — the same minified/obfuscated first-party signal minified-code and obfuscated-code use, recognized libraries excluded? Does the archive carry no transpiled source kind (.ts, .vue, .scss…), which is what catches a non-JS build whose scripts are copied verbatim? And is every shipped script byte-identical to a same-named file in the archive — the question that sees webpack, Vite, and a build that copies from submodules? The finding names no file, since its subject is the submission as a whole, so the entry carries no location line.

When it fires The add-on's built XPI is the same code that was submitted as a source archive: readable, not transpiled, and shipping no script that differs from the archive's copy. A separate source-code archive is therefore not required for this add-on. A source submission is needed only when the shipped code is minified, transpiled, bundled or otherwise not what the developer wrote, and it moves the add-on into a separate, considerably slower review process; a plain XPI submission is usually reviewed much faster. The developer is asked to stop sending the archive. This review itself is unaffected — it is a full source review either way.
