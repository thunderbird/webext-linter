Self-hosted update URL error

update-url

What it detects

A manifest that declares an update_url. It points Thunderbird at a developer-controlled update manifest, so the add-on's next version is installed from that URL instead of ATN — bypassing review. A later version could ship code that was never reviewed.

The check looks at the manifest only, and at both places update_url may sit: the current browser_specific_settings.gecko and the deprecated MV2 applications.gecko alias. It fires for either location, in any manifest version, and reports each present location on its own line. The manifest inspected is the shipped one (the built XPI), so a clean source manifest cannot mask a self-hosted update.

When it fires The add-on is told that its update_url directs Thunderbird to install updates from a self-hosted location instead of ATN, that such updates bypass review, and that update_url must be removed from browser_specific_settings.gecko (or applications.gecko).

Source of truth: src/checks/rules/update-url.js and its entry in assets/registry.yaml.
