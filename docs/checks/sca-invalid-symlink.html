Symbolic link out of the submission error

sca-invalid-symlink

What it detects

A symbolic link in the submitted source that leads outside the submission, or to a target that does not exist. A link is never followed and never read, so whatever it names sits outside everything the review reads: the build would compile code nobody looked at, and nobody else could reproduce it.

A link pointing to another location inside the submission is ordinary tree layout and is not reported. Its target is walked and reviewed under its own real path, so the code is covered wherever the link sits. That is the whole difference from the add-on itself, which may carry no link at all — see xpi-packaged-symlink.

These are real links on disk because the source archive is unpacked by the reviewer, with a tool that creates them. Each link is followed to its end before the question is asked, so a chain that starts inside the submission and leaves it is judged by where it actually arrives. Each rejected link becomes one error finding, and its location line says which of the two it was.

When it fires The add-on is told which links lead out of the submitted source or to a missing target, and asked to replace each one with the actual files, or to remove it where the build does not need it. A link to another location inside the submission is explicitly fine.

Source of truth: src/checks/rules/sca-invalid-symlink.js (fed by the symlink classification in src/addon/load.js) and its entry in assets/registry.yaml.
