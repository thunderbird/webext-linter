Unused default_locale error

default-locale-unused

What it detects

An add-on whose default_locale manifest key names no folder in _locales/ - including an add-on that ships no _locales directory at all. A default locale points at the localized message files of that folder, and when the folder is not there Thunderbird refuses to load the add-on. The name is matched as Thunderbird matches it, with _ read as -, so en_US is found in an _locales/en-US/ folder. The finding is located on the default_locale line in the manifest.

This is the mirror image of the default-locale-missing check, which covers the opposite mistake of shipping a _locales directory with no default locale declared. This check only acts when a default locale is declared; if the manifest did not parse, or no default locale is declared, or the folder it names is present, it stays silent.

When it fires The add-on is told the manifest declares a default_locale for which it ships no _locales folder, so Thunderbird will refuse to load it, and is asked to add that folder's message files, or correct or remove default_locale. The location line names the folder that is missing.

Source of truth: src/checks/rules/default-locale-unused.js and its entry in assets/registry.yaml.
