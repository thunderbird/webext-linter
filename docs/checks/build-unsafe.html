Unsafe build process error

build-unsafe

What it reports

A source-code submission whose build the reviewer held unsafe to run: it would fetch or run code from outside the dependencies declared in package.json and the lock file, or do something they will not run on their machine. Nothing was built.

It runs only under --llm-review, where the reviewer makes one decision about the build in the preparation, right after reading the agent's build report and its verdict. After an unsafe verdict they may trust it and build nothing, or clear the issues and let the agent build anyhow. After either verdict they may override it with reasons of their own why building is unsafe. Where that decision holds the build unsafe (when: build-judged AND NOT build-safe), this check reports it, and nobody is asked to build. Trusting the verdict reports each issue the build analysis listed in build-issues.md, at its file and line, with what the agent said it does. Reasons of their own report one finding carrying those reasons instead. Where nobody decided, build-review asks instead.

When it fires The add-on is told that its build process is not safe to run, since it fetches or runs code from outside the dependencies declared in package.json and the lock file, and that the build must use only those dependencies. The reviewer's own reasons follow it, where they gave some.
It aborts the review It settles the submission on its own: the developer’s text ends on the reason it is incomplete (“Build process issues”), and no build question is asked.

Source of truth: src/checks/rules/build-unsafe.js, the preparation's build decision (src/prepare/steps.js) and the entry in assets/registry.yaml.
