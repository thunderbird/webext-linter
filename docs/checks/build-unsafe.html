Unsafe build process error

build-unsafe

What it reports

A source-code submission whose build the reviewer judged unsafe to run: it fetches or runs code from outside the dependencies declared in package.json and its lock file.

Nothing in the files decides it, so the check raises nothing itself, and a review with no agent never lists it. Under --llm-review a source review opens with its build. The agent writes the build report and judges the build safe or unsafe. After an unsafe judgement the reviewer is shown the report's safety section and asked how the review goes on: stop it, have the agent build anyway, or build it themselves. Stopping it reports this check.

The build steps run only where every check the build relies on ran. With one of them switched off (--checks-only / --checks-skip), nothing is judged or built here, and the reviewer builds the add-on themselves.

When it fires The add-on is told that its build process fetches or runs code from outside the declared dependencies, so it cannot be built safely for review, and that every part of the build must come only from those dependencies.
It aborts the review The reviewer’s “abort” settles the submission on its own: nothing is built, nothing further is put to a reviewer, and the developer’s text ends on the reason it is incomplete (“Build process issues”).

Source of truth: src/checks/rules/build-unsafe.js, the build-choice-unsafe phase and the entry in assets/registry.yaml.
