Unsafe build process error

build-unsafe

What it reports

A source-code submission whose build would fetch or run code from outside the dependencies declared in package.json and the lock file, or do something the reviewer will not run on their machine. Nothing was built.

Nothing in the files decides it, so the check raises nothing itself. A plain review asks build-reproduces-xpi instead, whose one response covers every reason. Under --llm-review that question is put to the reviewer alone in the built phase, with four answers, and answering Is unsafe to build reports this check in its place. Where the agent judged the build unsafe and built nothing, the step before the question says the reviewer may answer so.

When it fires The add-on is told that its build process is not safe to run, since it fetches or runs code from outside the dependencies declared in package.json and the lock file, and that the build must use only those dependencies.
It aborts the review It settles the submission on its own: nothing further is put to a reviewer, and the developer’s text ends on the reason it is incomplete (“Build process issues”). The build question is cleared, so this is the one build finding.

Source of truth: src/checks/rules/build-unsafe.js, the built phase and the entry in assets/registry.yaml.
