Reproducing the XPI from the source error

build-reproduces-xpi

What it asks

Every source-code submission asks the reviewer to build the add-on from the source and compare the result with the submitted XPI: does the build complete, from a clean copy with the dependencies installed exactly as the lock file pins them (npm ci, or pnpm install --frozen-lockfile), and does its result match what was submitted?

Reproducing the build is the reviewer's attestation that the shipped XPI comes from the source they read, which is what a source-code review rests on. The reviewer answers by comparing the build output the review links, where the agent built the add-on, or their own build, with the submitted XPI. Otherwise they report whether it does not reproduce, does not build, or is unsafe to build.

Decision flow

When it fires In a plain report, the add-on is told that the submitted source could not be built into the submitted XPI, so the review cannot continue, and that the instructions must be complete, the build must succeed from a clean copy, and the submitted XPI must be built from exactly the submitted source.
It aborts the review A reported answer settles the submission on its own. Nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections of a printed report (an aborted --llm-review hands over no to-do item at all), and the developer’s text ends on the reason it is incomplete (“Build process issues”). Under --llm-review the question is asked ALONE, in the built phase, right after the Build Review Details and before the sweeps - ask batches, and nobody may be asked to install an XPI in the same breath as being asked whether the source builds into it. Its four answers are Builds and reproduces, which clears it, and Does not reproduce, Does not build and Is unsafe to build, which clear it and report build-not-reproduced, build-fails or build-unsafe, so the developer is told why. It is asked under --llm-skip-manual too. A source whose preparation gave its rescue up reports build-fails without a question, since nothing clean was built from it.
