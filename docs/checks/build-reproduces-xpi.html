Build does not reproduce the XPI error

build-reproduces-xpi

What it asks

Every source-code submission asks the reviewer whether the build reproduces the submitted XPI: does what the source builds match what was submitted?

Reproducing the build is the reviewer's attestation that the shipped XPI comes from the source they read, which is what a source-code review rests on. The reviewer answers from the build diff the review wrote, or by comparing their own build with the submitted XPI. Files that differ only by what every build changes (a timestamp, a build id) still match. It is asked only once the build succeeded (Build failure), so a build that failed is never also reported as not reproducing the XPI.

When it fires The add-on is told that the XPI built from the submitted source differs from the submitted XPI, so the review cannot continue, and that the submitted XPI must be built from exactly the submitted source, by the build instructions it contains.
It aborts the review A “no” settles the submission on its own. Nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections of a printed report (an aborted --llm-review hands over no to-do item at all), and the developer’s text ends on the reason it is incomplete (“Build process issues”). Under --llm-review the question is asked ALONE, in the reproduced phase, after the build and before any other question - ask batches, and nobody may be asked to install an XPI in the same breath as being asked whether the source reproduces it. It is asked under --llm-skip-manual too.
