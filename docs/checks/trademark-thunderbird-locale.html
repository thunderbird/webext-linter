Thunderbird in a localized add-on name error

trademark-thunderbird-locale

What it detects

"Thunderbird" may appear in an add-on's name only in the trailing form "<name> for Thunderbird". This check judges that form for every name the add-on's locale files state, and what it does with each one depends on the language that locale declares.

A name from a locale whose tag says English is decided here and becomes a finding, because the policy is written in English. A name from any other locale is handed to a reviewer instead. Outside English the form cannot be recognised from the text alone: the allowed and forbidden readings share one shape, since "Conversations para Thunderbird" is allowed while "Settings de Thunderbird" is not, word order is not fixed because some languages place the brand first, and neither are word boundaries, because some write the connecting particle against the brand and others add a case ending to the brand itself. Answering it needs the meaning of a word, so a reader answers it.

Two names are left alone. One already carrying "Firefox", "Mozilla" or "MZLA" belongs to the brand check, which rejects it outright, so weighing its Thunderbird form would be a second question about a name that is refused either way. And a name the check could not read at all - an unparsable locale file, or a placeholder no locale defines - is reported as exactly that, never as a pass, since nothing was examined.

Those reviewer items go to the code review list rather than manual review because they are answerable from the package alone: every locale file ships inside it, and each one's directory names its language. A name the manifest states literally carries no such tag, so it belongs to the sibling check instead.

When it fires The add-on is told that "Thunderbird" is not allowed in its name except as "<name> for Thunderbird", and that this applies to translations of the name as well as the original.

Source of truth: src/checks/rules/trademark-thunderbird-locale.js and its entry in assets/registry.yaml.
