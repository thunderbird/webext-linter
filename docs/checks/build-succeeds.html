Build failure error

build-succeeds

What it asks

Every source-code submission asks the reviewer whether the build succeeded: following the build process from a clean copy of the source archive, with the dependencies installed exactly as the lock file pins them (npm ci, or pnpm install --frozen-lockfile), did every step complete? Both refuse to install when package.json and the lock file disagree, and that refusal is a failed build.

Nothing in the files can answer that - only a build can - so the question is raised on every source review, anchored at the submission's package.json (or at no file, where the source documents no build at all). The reviewer answers it from the build diff the review wrote, or from their own build where they declined the one offered. Whether the build reaches for an undeclared source is settled before anything is built (Build process review), and whether the result matches the shipped XPI is the next question (Build does not reproduce the XPI).

When it fires The add-on is told that the submitted source could not be built by following its build instructions, so the review cannot continue, and that the instructions must be complete and the build must succeed from a clean copy of the submitted archive.
It aborts the review A “no” settles the submission on its own. Nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections of a printed report (an aborted --llm-review hands over no to-do item at all), and the developer’s text ends on the reason it is incomplete (“Build process issues”). Under --llm-review the question is asked ALONE, in the built phase, after the build and before any other question - ask batches, and nobody may be asked to install an XPI in the same breath as being asked whether the source reproduces it. It is asked under --llm-skip-manual too.
