Remote resources error

remote-resources

What it detects

Code loaded from somewhere other than the add-on's own package. Remote scripts and libraries cannot be reviewed, so everything the add-on runs must be bundled with it.

A deterministic pre-flight scans HTML, CSS, JavaScript and the manifest for remote loads: remote <script>/<link>/<iframe> and media in HTML, remote @import/url() in CSS, remote import()/importScripts() and module imports, runtime <script> injection, remote WASM, and a content security policy that permits a remote script source. Each of those definite remote loads is a finding directly. Cases static analysis cannot resolve — a non-literal URL, or an inline data:/blob: script source — carry the offending file to the model, which judges whether the loaded code is remote.

One kind of remote load is neither a finding nor a question for the model: one inside an HTML or CSS file whose content matches a published file of a known upstream library release. That line is the release's, not something the developer wrote — so it goes to the reviewer (is shipping it as published acceptable here?) and never to a model, since no verdict on where the URL points would change that. It turns on the content match, not on the declaration: a file that was declared but could not be matched is reviewed as the developer's own code, so its remote loads stay findings.

Three limits are worth knowing. The match is EOL-normalized, so it says the content is the release's, not that every byte is identical. It can also be earned without any declaration, by an exact content-hash match against a published file of a pinned package.json dependency — so the matched file is not necessarily one the add-on needs. And only the shipped XPI is ever matched against upstream, so a source-code (SCA) review never reaches this lane. Such an item reaches the human report only, which is the point of raising it: the JSON report carries only what the tool is certain of, so a case that would otherwise be an error there stops being grounds to reject the submission before anyone has read it.

When it fires The add-on is told that remote code is loaded from the named source, that remote scripts and libraries are not allowed, and is asked to bundle all code with the add-on so it can be reviewed.

Source of truth: src/checks/rules/remote-resources.js and its entry in assets/registry.yaml.
