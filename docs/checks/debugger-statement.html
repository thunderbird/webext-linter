Debugger statement error

debugger-statement

What it detects

An unconditional debugger statement left in shipped code. Such a statement halts execution whenever developer tools are open, so it does not belong in a released add-on.

The check looks only at the developer's own authored code; bundled, minified or otherwise non-authored files are skipped. Every remaining debugger statement is raised for a reviewer. An enclosing if is not read as a licence: a condition on runtime data — a message, a tab, a user setting — still fires in normal use, so only reading the condition says whether a build or configuration flag keeps the statement away from users.

When it fires The reviewer is asked to read the enclosing condition, if any, and decide whether a build or configuration flag keeps the statement away from users. Where they conclude it runs unconditionally, the add-on is asked to remove it or move it behind such a flag.
