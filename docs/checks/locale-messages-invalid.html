Unreadable _locales messages.json error

locale-messages-invalid

What it detects

A _locales/<lang>/ folder whose messages.json Thunderbird cannot read. When it installs an add-on, Thunderbird reads every folder under _locales and refuses the whole add-on if one has no messages.json, or one that is not UTF-8 or UTF-16 text, not JSON as its loader reads it (only // comments are allowed), or not messages data: an object whose every entry is an object with a string message.

The file is read exactly the way Thunderbird reads it, so a messages.json with // comments or a byte-order mark is fine, and one with a trailing comma, a block comment or a stray Latin-1 byte is not. An empty locale folder counts too: it has no messages.json. Thunderbird treats en_US and en-US as one locale and reads only one of the two folders, so where one of them is fine the other is not reported.

Decision flow

When it fires One error finding per folder, at its messages.json, saying whether the file is missing, cannot be read, or is not messages data.

Source of truth: src/checks/rules/locale-messages-invalid.js, the locale scan in src/lib/locales.js and its entry in assets/registry.yaml.
