Confirming the XPI could not be reproduced error

build-not-reproduced-confirm

What it asks

Under --llm-review, where the agent built the add-on in the build check, the linter compares what it built with the submitted XPI: the same files at the same paths, each with the same contents, where only line endings may differ. A match proves that the shipped XPI comes from the source the review reads, so nobody is asked. This check asks only where the linter could not confirm it: the comparison found no match, or the agent's build failed. It asks the reviewer: "It seems as if the XPI could not be reproduced. Please confirm."

It runs only where the reviewer held the build safe and the agent's build did not reproduce the XPI (when: build-judged AND build-safe AND build-attempted AND NOT build-reproduced). Where the reviewer built the add-on themselves, build-reproduces-xpi asks instead.

Decision flow

flowchart TD
  A["The agent's build"] --> M{"Does the linter's comparison
match the submitted XPI?"}
  M -- yes --> NA([nothing is asked: the review goes on])
  M -- "no, or the build failed" --> Q{"It seems as if the XPI could
not be reproduced. Please confirm."}
  Q -- "The built add-on does not match
the submitted XPI" --> NR([ERROR: build-not-reproduced])
  Q -- "The build failed" --> BF([ERROR: build-fails])
  Q -- "The XPI was correctly reproduced
[override]" --> OK([cleared: the review goes on])

It aborts the review It is asked ALONE, in the built phase, right after the Build Review Details, which show the agent's build and the linter's comparison (LLM_BUILD_XPI_MATCH). Two answers clear it and report build-not-reproduced or build-fails, so the developer is told why, and the review is aborted late. The override clears it, and the review goes on.
