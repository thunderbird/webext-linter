Missing referenced file error

bundled-files

What it detects

A file the add-on points to but does not actually ship. References are gathered from two places, and both come from the schema rather than a list kept here: manifest entries, meaning every key the schema types as an extension-relative path (content script JS and CSS, background scripts, pages and service workers, options pages, action popups, icons and every default_icon / theme_icons, ruleset paths, theme images, and an Experiment's schema and parent scripts), and file-loading API calls in the code (icon, theme and menu registration, script and CSS injection, packaged-URL lookups, tab creation, popup assignment, and so on).

Coverage is therefore the schema's. A key it types loosely, or does not declare, is not followed — and noticing that would need a hand-maintained list of the keys to expect, which is the thing the schema walk exists to avoid: such a list silently loses a key (icons is easy to forget) and nothing then reports the file it pointed at.

Only references that look like packaged files are judged — relative or root-relative paths with no URI scheme. Remote URLs, pseudo-schemes such as moz-extension or about, and bare fragments are left to other checks. Manifest references are anchored by the JSON path to the slot that holds them, so one file named in several slots — icons.16 and icons.48 for one image is the norm — gives each slot its own line rather than repeating the first. A localized __MSG_…__ path is skipped, since which file it names depends on the locale. Page-relative loader references are resolved against the calling script's host page directory, the rest against the package root. Loader references are read only in scripts reachable from an entry point — an orphan script never runs, so its references are dead-code noise, an unused-files matter. Each remaining candidate that is absent from the package produces a finding.

When it fires The add-on is told that the named path is referenced but not bundled, and asked to include every referenced file in the package.
