API newer than strict_min_version error

strict-min-version-api

What it detects

The add-on declares a lowest supported Thunderbird release through strict_min_version, but calls a WebExtension function or event that was only added in a later release. On those older installs the API does not yet exist, so an unconditional call throws.

Only real, schema-resolved APIs are considered — a misspelled or non-existent name is left to the unknown-API check. The same too-new API can be used safely if it is guarded so it runs only where it exists (optional chaining, a typeof or existence test, a guard clause earlier in the function that returns or throws when the API is missing, or a runtime version gate). Which constructions do so is open-ended, and reading a real guard out of the AST is a judgement whose wrong answer rejects a working add-on — so every site escalates and a reader settles it in the call's own file. Each call site is listed separately: a flag can cover one use and not the next.

When it fires The add-on is told it sets strict_min_version too low while using functions or events added in a later Thunderbird, and is asked to raise strict_min_version or guard the call.
