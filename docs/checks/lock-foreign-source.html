Lock file installs from an unsupported source error

lock-foreign-source

What it detects

A source-code submission whose committed lock file installs a package from a source other than the npm registry or GitHub. The dependency audit identifies a package by its name and version, while npm ci and pnpm install --frozen-lockfile fetch it from the URL the lock records, so an entry resolved elsewhere installs bytes the audit never read.

GitHub is accepted, because a package.json may declare a GitHub dependency. A root dependency declared as a registry release but locked to GitHub is reported too: it is audited as the npm package and installed from somewhere else. An entry with no recorded source is a registry install, and a local file: or linked package is the submission's own code, judged by other checks.

When it fires The add-on is told which packages its lock file installs from an unsupported source, and that every dependency must install from the npm registry or, where package.json declares one, from GitHub, with a regenerated lock file.
It stops the review Like the other build checks, this one settles the submission on its own (“A build that cannot be reproduced”): the install would run, but what it fetches is not what the audit read, so reproducing the build attests nothing - and it would pull code from a developer-chosen host onto the reviewer's own machine.
