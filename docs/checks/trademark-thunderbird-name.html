Thunderbird in an unlocalized add-on name error

trademark-thunderbird-name

What it detects

"Thunderbird" may appear in an add-on's name only in the trailing form "<name> for Thunderbird". This check looks at a name the manifest states directly, rather than through a localized placeholder, and puts every name outside that form to a reviewer. It never rejects one itself.

The reason is narrow. Recognising the allowed form outside English needs the meaning of the word before the brand, so the language has to be settled first, and a name written directly in the manifest carries no locale tag. Nothing in the package says what language it is in, which is why this question goes to manual review while its sibling, whose names arrive tagged with their language, goes to code review.

A name already carrying "Firefox", "Mozilla" or "MZLA" is left alone: the brand check rejects it outright, so asking about its Thunderbird form as well would be a second question about a name that is refused either way.

One consequence is deliberate: a name that looks like an obvious English violation is put to a reviewer rather than rejected outright, because the same shape in another language can be the allowed form. A wrong rejection costs the developer a release, while a question costs a reviewer a glance.

When it fires The add-on is told that "Thunderbird" is not allowed in its name except as "<name> for Thunderbird". The check itself only raises the question, so nothing is reported to the developer until a reviewer confirms it.

Source of truth: src/checks/rules/trademark-thunderbird-name.js and its entry in assets/registry.yaml.
