Unreviewable build dependency error

unpopular-source-dependency

What it detects

A declared dependency that could not be confirmed to be a widely-used library. This check runs only for a source-code submission, where the dependency code is pulled in at build time: it is absent from the readable source and mangled in the built add-on, so a dependency that is not trusted by ubiquity cannot be reviewed at all.

Before the review begins, a network pre-step looks up the popularity of each package.json dependency: monthly downloads for an npm package, or stargazers for a GitHub source. A dependency below the trust bar is recorded, and this check turns each one into a finding anchored at its declaration line. The reject only ever fires on a confirmed reading below the bar: a package the registry has no reading for records nothing, and a lookup that gets no answer ends the review instead. A dependency that clears the bar is trusted by ubiquity and never reaches here.

Build dependencies are held to the same bar, for the reason they are also checked for known vulnerabilities: the reviewer installs them and runs them on their own machine to reproduce the build. Refusing only the vulnerabilities that have been written down, while accepting a package nobody has vetted, would guard against the risk we can name and not the one we cannot. The remedy differs, though. A dependency you ship can be included readable in the source instead, and a build tool cannot, so there the answer is a widely-used equivalent - or removing it, where reproducing the shipped add-on never needed it. The archive is submitted so the build can be reproduced, and a package no step of that build requires is one the reviewer is asked to install for nothing. For a package with no popular counterpart, such as a types-only package used while editing, that is the only route open.

Decision flow

flowchart TD
  A["A package.json dependency"] --> G{"Source-code submission?"}
  G -- no --> S([skip])
  G -- yes --> B{"Popularity reading available?"}
  B -- "no (registry has none)" --> S
  B -- yes --> C{"Above the widely-used bar
(npm downloads or GitHub stars)?"}
  C -- yes --> OK([no finding])
  C -- no --> ERR([ERROR: unreviewable build dependency])

When it fires The add-on is told a declared dependency could not be confirmed to be widely-used, and that it needs to be packaged with the add-on so it can be reviewed.

Source of truth: src/checks/rules/unpopular-source-dependency.js and its entry in assets/registry.yaml.
