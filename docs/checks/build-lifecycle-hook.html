Build install hook error

build-lifecycle-hook

What it detects

A source-code submission whose package.json declares an npm install lifecycle hook — a preinstall, install, postinstall, prepare, prepublish, prepublishOnly, or prepack script. These run automatically when the reviewer installs the declared dependencies, before the build even starts, so a hook that fetches and runs remote code is a supply-chain vector the dependency audit — which only reads the declared package.json and lock file — never sees.

The build process review asks about hooks too, among every other build step. This check names each hook on its own. Legitimate hooks exist (a husky prepare, a local codegen step) and only the command itself says which kind this is, so the scan cannot settle it. Each declared install hook escalates to Extended Code Review, anchored at its line in package.json, with the hook and its command on the locus — so the hooks collapse into a single entry the reviewer reads command by command.

When it fires The reviewer is asked to read each hook's command and confirm it only runs local build steps, fetching or executing nothing remote (curl/wget, a download-and-run, or a git clone of an unpinned repo). Nothing is said to the developer unless the reviewer concludes a hook does reach the network, in which case the entry's suggested response asks for it to be removed.
It aborts the review, but only once a hook is reported This check settles the submission on its own, but it reports nothing by itself: a reviewer has to conclude first that a hook reaches the network. A hook cleared as a local build step aborts nothing. Once one is reported, nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections of a printed report (an aborted --llm-review hands over no to-do item at all), and the developer’s text ends on the reason it is incomplete (“Build process issues”). Under --llm-review the agent settles it in the settle phase, after the build question. The hooks are screened before any install by the agent's build safety judgement and the reviewer's permission to build.
