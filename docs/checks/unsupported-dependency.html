Unsupported dependency source error

unsupported-dependency

What it detects

A dependency from a source the review cannot identify or verify. Only two sources can be vetted: an npm package and a GitHub URL, which is gated by popularity. Everything else is rejected. Whether the release a spec names can be pinned at all is a separate question, answered by other checks.

In a built XPI, the vendor resolver reads the package.json dependencies once and classifies each by its source. A local file reference, a link or workspace reference, a tarball URL, or a git source that is not GitHub cannot be resolved to a known upstream, so it is set aside as unsupported. Build dependencies are left alone there: nothing is installed from a built XPI and they declare no bundled files.

In a source-code submission, package.json is not read for dependencies: the committed lock file is, because it is what the install follows. What this check reports there is an install from a local path the archive does not hold as a folder - a path outside the source root, one the archive does not contain, or a local tarball. A local folder inside the source root is the submission's own code, reviewed like any other file, so nothing is said about it. A remote tarball or a git source that is not GitHub is reported by lock-foreign-source. Build dependencies count as much as shipped ones: the reviewer installs them to reproduce the build, so an unreviewable one is code that runs on the reviewer's machine.

This check turns each entry into a finding, anchored at its declaration line in package.json or at its entry in the lock file.

When it fires The add-on is told the dependency is declared from a source the review cannot identify or verify, and that only npm packages and GitHub sources are supported. The two submission types are told slightly different things. An add-on submitted as a built XPI is asked to re-declare it as a pinned npm package or a GitHub source, or to bundle the library as authored code so it can be reviewed directly - pinning is part of that answer because a shipped declaration must name one release. A source submission is asked only to re-declare the source, with the note that this applies to build dependencies too, since the reviewer installs and runs them, and that a library it bundles can instead be included non-minified in the archive.
