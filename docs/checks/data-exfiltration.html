User-data exfiltration error

data-exfiltration

What it detects

The user's sensitive data, such as messages, contacts and credentials, or anything computed from it on the user's machine, leaving the machine where the user would not expect it, by any route.

A deterministic scan of the developer's own JavaScript collects two kinds of site. An overt transmission (fetch, XMLHttpRequest, WebSocket, EventSource, navigator.sendBeacon or an HTML form submission) to a remote or dynamically-built host. And a URL channel (a resource src or href, a stylesheet url(), window.open() or a page navigation) to a host that is not local, whose URL is built with a runtime value or carries a user-data API call. A static URL there sends nothing of the user's. Each site is escalated, labelled with its route. This check emits no finding of its own.

A site is reported unless no sensitive data leaves, the user set the transmission up (picked the service, entered the destination or a key, turned on an off-by-default setting), or sending this data to this destination is the add-on's single purpose, as the add-on states it. Thunderbird has no built-in data-collection consent prompt. Where that purpose might cover it but the add-on does not say so, the reviewer decides, with the add-on's listing in view.

Mail the add-on composes and sends itself (for example with compose.beginForward, beginNew or sendMessage), and every route the scan does not know, are reached through the sweep, which checks at least the routes above and then looks beyond them.

When it fires The add-on is told the listed code locations send the user's sensitive data to a remote server where the user would not expect it. Sensitive data may leave only where the add-on needs it for its functionality, and only where the user set the transmission up or sending it is the add-on's stated single purpose. It is asked to let the user set it up on an options page that says what is sent and to whom, or to remove the transmission.

Source of truth: src/checks/rules/data-exfiltration.js and its entry in assets/registry.yaml.
