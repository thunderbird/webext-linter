Invalid package.json error

sca-package-file-invalid

What it detects

A source-code submission whose package.json cannot be used: it is not valid JSON, or it is valid JSON that is not an object. npm reads neither, so the build the package file defines cannot be run and the shipped add-on cannot be reproduced from the archive.

Two things make a package file unusable, and both are reported here: it cannot be read at all, or it reads perfectly well and holds something other than a JSON object - an array, a string, a number. They are worded apart because a developer would check which it is: one will not open, the other opens fine and simply is not a package file. Which case failed is shown on the location line, so the remedy is stated once.

The file is read once for the whole review, and every reader of it sees the same answer: a package file this check calls unusable is exactly the one the dependency checks found nothing in. A leading byte-order mark is not a fault - npm reads a package file carrying one, so this does too.

A package.json that is absent rather than broken is Missing package.json, its sibling. Presence is decided by name and usability by reading, so exactly one of the two speaks. Like that check it reports even where the shipped add-on is the archive’s own code, because a package file npm cannot read leaves nothing to reproduce the build from either way.

When it fires The add-on is told that its committed package.json cannot be read, so the build it defines cannot be run, and is asked to commit a valid one. The finding is anchored at package.json, and the location line says which of the two ways it failed.
It stops the review This check is one of the few that settle the submission on their own. When it reports, nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections, and the developer’s text ends on the reason it is incomplete (“A build that cannot be reproduced”). Every remaining question depends on running a build whose package file cannot be read, so the work it would otherwise put to a reviewer cannot change the outcome.
