Check the package for unacceptable content error

unacceptable-package-content

What it detects

This check scans nothing. Whether what an add-on ships is spam, inappropriate, misleading or low-effort is not decidable from the bytes, so what it contributes is a blind spot: a standing brief naming what to look for in the package - its name and description in manifest.json, its icons, and any text, images or media bundled with it.

Every review prints that brief under Standard Code Review, for a reviewer covering it by hand. When an agent is reviewing, it sweeps for the same thing and hands back what it finds; each location comes back as a case of this check, screened by the agent and put to the reviewer if it survives. The agent can drop a candidate but never rule on one - whether content breaches Mozilla's Acceptable Use Policy is a person's judgement.

Everything judged here lives inside the submitted package, so every fix needs a new version. The ATN listing is judged separately by unacceptable-listing-content.

When it fires The developer is told that content shipped inside the add-on does not meet our content requirements, and is asked to correct it and submit a new version.
