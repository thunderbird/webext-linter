Missing package.json error

sca-package-file-missing

What it detects

A source-code submission that carries no package.json. The archive exists so a reviewer can reproduce the build that produced the shipped add-on, and without a manifest there is nothing to reproduce.

The build's entry point is the package.json at the root of the submission, the way manifest.json is the review's: the build corpus is collected by following it. Its absence is therefore the absence of a build, and that is all this check reports. Presence is decided by name, not by reading the file: one that exists but cannot be used is not missing, and Invalid package.json reports it instead. The pair is shaped like Missing lock file and Invalid lock file, the other file this build cannot run without.

Deliberately nothing more. The build files could have been left out by accident or never have existed, and nothing in the archive says which.

It stays silent when the build uses a package manager this review does not support: that is a fault of its own, reported once by the check whose subject the tool is, which stops the review just as this one would.

It reports even where the shipped add-on is the archive's code - not minified, not transpiled, every script byte-identical. That the shipped bytes are readable says nothing about whether this source produces them, which is what reproducing the build establishes, and with no build there is nothing to reproduce. What yields instead is the advice: Source archive not required is withheld from a submission whose build cannot be run, rather than this rejection being withheld from it.

When it fires The add-on is told that its source archive contains no package.json, so there is no build process the shipped add-on can be reproduced from. The finding names no file, because it is about something the archive does not contain.
It stops the review This check is one of the few that settle the submission on their own. When it reports, nothing further is put to a reviewer: the report drops every to-do item they would have been asked, keeps the code-review sections, and the developer’s text ends on the reason it is incomplete (“A build that cannot be reproduced”). Every remaining question depends on reproducing a build that is not there, so the work it would otherwise put to a reviewer cannot change the outcome.
