Build process review error

undeclared-build-source

What it detects

In a source-code submission the reviewer builds the add-on from the readable source, but the dependency audit only reads the root package file and lock file. A build script or config could ignore the package file and pull code or resources from an undeclared source, leaving the declared dependencies a clean decoy.

The build analysis collects the build files once, when this check first asks for them, over the build-relevant files (collected by following the package file, so build output and tooling the build never runs are never sent). Nothing in them says for certain what that build does, so this check emits no finding of its own and escalates EVERY source-code submission - one whose source documents no build at all included - for its build to be read: does any step reach outside the declared dependencies?

Under --llm-review the agent settles it in the settle phase. A source review builds first, so the same question is screened before anything is built by the agent's safety judgement and the reviewer's build choice (Unsafe build process). In a review with no agent it is listed under Extended Code Review, ahead of the build question. Whether the source then builds into the shipped XPI is a question of its own (Source does not build into the XPI). The steps the analysis could not statically follow (an opaque orchestrator, yarn or bun, a network fetch in a script) are named in the entry, which anchors at the submission's own package.json where there is one.

When it fires The add-on is told that every part of the build must come only from the dependencies declared in the package file and lock file, never from a remote source.
It aborts the review A build that reaches for an undeclared source settles the submission on its own: nothing further is put to a reviewer, and the developer’s text ends on the reason it is incomplete (“Build process issues”).
