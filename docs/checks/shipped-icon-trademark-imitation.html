Check the shipped icons for trademark or logo imitation error

shipped-icon-trademark-imitation

What it detects

This check scans nothing. Whether an image imitates or incorporates the Thunderbird, Firefox or Mozilla logo is a judgement about what it looks like, not something decidable from the bytes, so what it contributes is a blind spot: a standing brief naming what to look for among the icons the package ships.

Every review prints that brief under Standard Code Review, for a reviewer covering it by hand. When an agent is reviewing, it sweeps for the same thing and hands back what it finds; each location comes back as a case of this check, screened by the agent and put to the reviewer if it survives. The agent can drop a candidate but never rule on one - whether an icon takes a mark nobody else may use is a person's judgement.

The icons judged here are the ones inside the submitted package, so a fix needs a new version. The icon on the ATN listing page is a different image with a different remedy, judged by the manual icon-trademark-imitation check, where the fix is a listing edit. Whether shipped content is otherwise acceptable - spam, misleading, low-effort - is a different question, asked of the same package by unacceptable-package-content, whose brief covers icons too on those grounds.

When it fires The developer is told that an icon shipped inside the add-on imitates or incorporates a Mozilla trademark, which Mozilla's Trademark Policy does not allow, and is asked to use a distinct icon and submit a new version.
