Dependencies changed for the review info

sca-dependencies-changed

What it detects

A source-code submission reviewed from a rescued copy. When the submitted lock installs a package with a known high or critical advisory, the preparation of the review copies the source and reduces the copy's dependencies to what the release build uses, then, where that is not enough, applies the package manager's audit fix. A copy the linter's own audit finds clean is reviewed instead of the submission. A copy still vulnerable after the fix is deleted, and the submission is reviewed as it was submitted, aborted by those vulnerabilities.

The developer's own package.json and lock file still have the vulnerabilities, so this check says so once, at package.json, when the copy's lock differs from the lock of the root it was made from: a release it no longer installs or newly installs, or a package it no longer records as declared or newly does. Like every dependency question of a source-code review, it reads the locks alone, not package.json. It lists nothing: the developer's own npm audit or pnpm audit names what to fix, against their own lock.

When it fires The developer is told that the review used their dependencies with changes made to get past known vulnerabilities, that their own package.json and lock file still have them, and to run their package manager's audit before the next submission.
It never aborts the review The finding is information for the developer. Whether the build of the rescued copy reproduces the shipped add-on is asked by the review itself, like for any source-code submission.
